## 1. Introduction and Problem Definition  (~1 page)
- Who the users are: small online sellers (UMKM) on Tokopedia who receive hundreds of free-text reviews.
- Why star ratings are not enough: they do not say *which emotion* (anger vs sadness vs fear) or *what it is about*.
- Task statement: 5-class emotion classification of Indonesian reviews + rule-based aspect tagging.
- Contributions: baseline vs IndoBERT comparison, preprocessing ablation, error analysis, a working dashboard.

## 2. Dataset and Exploratory Analysis  (~1.5 pages)
- Source and citation of PRDECT-ID; collection platform; size; label schema (5 emotions + sentiment).
- Cleaning decisions: exact duplicates dropped (count from `eda_summary.json`), missing values.
- Table: label distribution. Figure: `results/eda_label_distribution.png`. Figure: `results/eda_length_hist.png`.
- Discuss class imbalance (imbalance ratio) and why Macro-F1 is the headline metric.
- Split: stratified 80/10/10, seed 42, generated **before** preprocessing (state this explicitly - it is the leakage control).

## 3. Preprocessing  (~1 page)
- Pipeline: lowercase -> cleaning -> slang normalisation (`new_kamusalay.csv`) -> optional stopword removal.
- Why no stemming (slow, little benefit for TF-IDF/BERT). Why negations are kept in the stopword step.
- Why IndoBERT gets text without stopword removal.
- **Ablation table** (`results/ablation.csv`): raw vs cleaned vs cleaned+slang (+ the stopword extra), validation Macro-F1.
  Report honestly if differences are small - the validation set is small, so differences of a few thousandths are noise.

## 4. Models and Experimental Setup  (~2 pages)
- Baseline: TF-IDF (1-2 grams, min_df=2, sublinear tf) + Logistic Regression; tuning grid for `C` and `class_weight` (`results/baseline_tuning.csv`); chosen configuration.
- IndoBERT: `indobenchmark/indobert-base-p1`, 3 epochs, lr 2e-5, batch size, max length 128, best checkpoint by validation Macro-F1 (`results/indobert_training_log.json`), trained on Colab T4.
- Evaluation protocol: tune on validation, touch the test set once.
- **Main results table** (`results/model_comparison.csv`): Macro-F1, Weighted-F1, Accuracy, macro Precision, macro Recall.
- Per-class results (`per_class_*.csv`) and a short discussion of which emotions are easy / hard.

## 5. Error Analysis  (~2 pages)
- Normalized confusion matrices for both models (`results/confusion_matrix_*.png`); which emotion pairs are confused.
- Method: `<N>` misclassified test samples drawn round-robin across true classes (`results/errors.csv`), categorised **by hand** into four categories.
- Table: count per category (`results/error_category_counts.json`).
- For each category: a definition, 3 concrete examples (`results/report_examples.md`) and one sentence of explanation.
  - Sarcasm/Irony - Ambiguous/Multi-Emotion - Slang/Spelling Outliers - Annotation Noise
- Say clearly that the sample is small and the categorisation is subjective (state who labelled, and whether two people agreed).

## 6. Seller Insights Module  (~1 page)
- Lexicon of five aspects (`src/insights.py`), primary-aspect rule (most keyword hits, ties -> first mentioned).
- Aspect x emotion matrix and the "where to look first" summary; one worked example from the demo CSV.
- Limitations: keyword matching is context-blind, generic words ("bagus", "cepat") are ambiguous, no sentence-level aspect sentiment.

## 7. Application  (~1.5 pages)
- Architecture diagram: data -> preprocessing -> {baseline, IndoBERT} -> insights -> Streamlit.
- Screenshots: Single Review Inspector (prediction, probability bar chart, aspect tag) and Batch Seller Dashboard
  (emotion breakdown, aspect x emotion matrix, export table).
- Model switching, caching, CPU inference notes.

## 8. User Evaluation  (~1 page)
- Procedure: 3-5 participants, 15 minutes each (`docs/user_feedback.md`).
- Summarise answers to the three questions: clarity/accuracy, actionability, missing features.
- What you changed (or would change) because of the feedback.

## 9. Limitations and Future Work  (~1 page)
- Single dataset and a single platform; label noise; small test set; no confidence calibration.
- Aspect tagging is rule-based; no aspect-level emotion; no multi-label emotions.
- Future: aspect-based sentiment, calibration, active learning with seller feedback, larger/other Indonesian models.
